# cc16: C compiler for CPU16 (Phase 8)

cc16 is a C compiler for CPU16, written in TypeScript. It never touches the file system, so the same
code runs both on the Node command line and in the browser. Its output is a single assembly text that
as16 assembles. Every compiled program therefore runs on the same emulator, microcode model and real
board as hand-written programs.

A guided tour of the C examples, how to run them, and what you need to know when writing C for CPU16
(memory map, I/O addresses, the cost of operations): **[c-ornekleri.en.md](c-ornekleri.en.md)**.

```
source.c ─► preprocessor ─► parser (typed AST + constant folding) ─► code generator ─► object (pieces)
                                                                                             │
crt0.s, rt.s, libc16.c (library) ─────────────────────────────────────► linker ◄─────────────┘
                                                                          │
                                                                  as16 text ─► as16 ─► 64 KB image (ROM 0x0000–0x3FFF)
```

| File | Role |
|---|---|
| `cc/lexer.ts` | lexer (pp-tokens, string/character escapes, UTF-8) |
| `cc/preprocess.ts` | `#include`, `#define`, the `#if` family, `#` / `##`, `__VA_ARGS__` |
| `cc/parser.ts` | C parser, type checking, implicit conversions, constant folding, initializers |
| `cc/codegen.ts` | code generation, register variables, peephole optimizations |
| `cc/object.ts` | object format (a list of "pieces"), turning `.s` files into objects |
| `cc/linker.ts` | symbol resolution, dead code elimination, ROM/RAM placement, branch relaxation |
| `cc/index.ts` | public API: `compile`, `buildProgram` |
| `cc/run.ts` | running in the emulator, a bus that catches writes to ROM |
| `cc/node.ts` / `cc/lib-vite.ts` | loading the library from disk (Node) / embedded in the bundle (Vite, browser) |
| `lib/` | `crt0.s`, `rt.s` (helpers), `libc16.c`, `include/*.h` |
| `tools/cc.ts` | the `cc` command line |

## Usage

```sh
npm run cpu16 -- cc cpu16/programs/c/hello.c --run          # compile and run in the emulator
npm run cpu16 -- cc program.c                               # program.hex (Intel HEX, for the EEPROM)
npm run cpu16 -- cc program.c -o program.bin                # raw binary (from 0x0000)
npm run cpu16 -- cc program.c -o program.s                  # linked as16 text
npm run cpu16 -- cc cpu16/programs/c/multi/main.c cpu16/programs/c/multi/util.c --run
npm run cpu16 -- cc a.c b.c rutin.s -I include -D DEBUG=1 --map --run
```

| Option | Meaning |
|---|---|
| `-o dosya` | output: `.hex` (default), `.bin` or `.s` |
| `--run` | run in the emulator; UART output (0xFF00) goes to the console, followed by the exit code |
| `--hedef rom\|bios` | `rom` (default), or a program that runs from RAM on top of the BIOS (below) |
| `--max N` | at most N instructions (default 50 million); cycles for the BIOS target |
| `-I dizin` | extra search directory for `#include "..."` |
| `-D AD[=değer]` | define a macro |
| `-O0` | turn off register variables and peephole optimizations |
| `--nostdlib` | do not link crt0 and the library (the program defines `__reset`) |
| `--map` | address/size table of the pieces |

Input files can be `.c` or `.s` (linkable assembly, see below).

### API (browser and Node)

```ts
import { buildProgram, compile, formatErrors } from "./cpu16/cc/index.ts";
import { LIB } from "./cpu16/cc/lib-vite.ts";   // in Node: import { loadLib } from "./cpu16/cc/node.ts"
import { runProgram } from "./cpu16/cc/run.ts";

const files = { "/proje/main.c": "...", "/proje/util.h": "..." };       // in-memory file system
const b = buildProgram(files, ["/proje/main.c"], { lib: LIB, defines: { N: "10" } });
if (b.errors.length) console.log(formatErrors(b.errors));            // [{ file, line, col, message }]
else console.log(runProgram(b.image).output);                         // b.ranges, b.symbols, b.map, b.asm

const c = compile(files, ["/proje/main.c"], { lib: LIB });            // { asm, errors }: as16 text only
```

Options: `lib`, `nostdlib`, `defines`, `includeDirs`, `readFile` (callback for files that are not in the
map), `optimize` (default `true`), `layout` (ROM/RAM limits). The compiled library is cached per `lib`
object.

## Supported C

Most of C99 (Phase 8 scope, stages 1–4):

- **Types:** `char` (8 bits, **unsigned**), `signed/unsigned char`, `short` and `int` (16 bits), `long` and
  `long long` (32 bits), `_Bool`/`bool`, `enum` (int), pointers (16 bits), arrays (including multidimensional),
  `struct`, `union` (anonymous members, flexible array member), function pointers, `typedef`, `const`, `volatile`.
- **Statements:** `if/else`, `while`, `do/while`, `for` (including a declaration in the init clause), `break`, `continue`,
  `return`, `switch/case/default` (dense cases become a jump table), `goto` and labels, blocks.
- **Expressions:** all integer operators (`* / %` and variable shifts through software helpers;
  multiplication by a constant becomes shifts and adds whichever side the constant is on: `10 * x`, `x * 10`),
  signed/unsigned comparisons, `&& || !` (short-circuit), `?:`, comma, compound assignments, `++/--`,
  `sizeof`, casts, pointer arithmetic and pointer difference, struct assignment / pass by value / return,
  compound literals `(struct P){1, 2}`, `__func__`.
- **Initializers:** global and local arrays, structs, strings, nested and designated initializers
  (`.a.b = 1`, `[3].x = 2`), arrays sized by their initializer, address constants
  (`int *p = &dizi[2];`, function pointer tables).
- **Variadic functions:** `<stdarg.h>` (`va_list`, `va_start`, `va_arg`, `va_end`, `va_copy`).
- **Preprocessor:** `#include "..."` (first the file's directory, then the `-I` directories) and `<...>` (library
  headers), object-like and function-like `#define`, `#`, `##`, `__VA_ARGS__`, `, ## __VA_ARGS__`, `#undef`,
  `#if/#ifdef/#ifndef/#elif/#else/#endif`, `defined`, `#error`, `#warning`, `#pragma once`, `#line`,
  `__FILE__`, `__LINE__`; predefined `__CPU16__`, `__CC16__`, `__CHAR_UNSIGNED__`, `__SIZEOF_INT__` ...
- **Multiple translation units:** `extern`, `static` (file-local functions and variables), linking mixed with
  assembly files.

Constant expressions (array sizes, `case` values, global initializers, `#if`) are evaluated at compile time
with the target's 16/32-bit rules; the same folding also applies to constant subexpressions inside function bodies.

### Type sizes and alignment

| Type | Size | Alignment |
|---|---|---|
| `char`, `_Bool` | 1 | 1 |
| `short`, `int`, pointer, `enum` | 2 | 2 |
| `long`, `long long` | 4 (low word first) | 2 |
| `struct` / `union` | by members, **rounded up to an even number** | 2 |

A decimal constant that does not fit in `int` becomes `long` (`32768` → `long`, so `-32768` is also `long`;
`INT_MIN` is defined as `(-32767 - 1)`). A hex/octal constant that does not fit in `int` becomes `unsigned int` (`0xFFFF` → `unsigned`).
All local variables live at even addresses in even-sized slots; struct copies are done word by word.

## Memory layout

```
0x0000 ┌──────────────────────────┐  ROM (writes are ignored)
       │ vectors:   0x0000 reset  │  one instruction each (B .start / B .irq / B .swi)
       │            0x0002 IRQ    │
       │            0x0004 SWI    │
       │ crt0, .text (code)       │  user code, then the library
       │ .rodata (const, strings) │
       │ .data initial image      │  __data_load
0x3FFF └──────────────────────────┘
0x4000 ┌──────────────────────────┐  RAM
       │ .data (initialized)      │  __data_start … __data_end   (crt0 copies the image here)
       │ .bss  (zeroed)           │  __bss_start … __bss_end     (crt0 clears it)
       │ heap ↑ malloc            │  __heap_start … __heap_end (= 0xFF00 − 0x400)
       │          ...             │
       │ stack ↓                  │  initial SP __stack_top = 0xFF00
0xFEFF └──────────────────────────┘
0xFF00   I/O: UART data register (putchar writes here)
```

- Code and constants (`const` globals, string literals) are in ROM. A program never writes to ROM; in the
  tests the writes below 0x4000 are counted and the count is checked to be zero (`cc/run.ts: RomGuardBus`).
- Initialized modifiable globals (`.data`) live in RAM; their initial values are in ROM, in the image at
  `__data_load`. **At startup crt0 copies this image to RAM** and clears `.bss`, then calls `main(0, 0)`.
- When `main` returns, `HALT` runs with the return value left in `r0` (`exit(n)` does the same).
- The linker reports "ROM taştı" (ROM overflow) or "RAM taştı" (RAM overflow) when the ROM contents
  exceed 16 KB or `.data + .bss + 1 KB stack` does not fit in RAM.

### crt0 sequence

1. `0x0000: B .start`, `0x0002: B .irq`, `0x0004: B .swi`
2. `SP = 0xFF00`
3. `__data_load → __data_start..__data_end` copied word by word
4. `__bss_start..__bss_end` cleared
5. `r0 = r1 = 0`, `CALL _main`, `HALT` (exit code in `r0`)

The IRQ/SWI entry saves r0–r3 and r7, calls the C function `irq_handler()` / `swi_handler()`, then `RETI`.
The library has empty defaults; a function with the same name defined in the program replaces them
(`<cpu16.h>`: `ei()`, `di()`, `halt()`, `UART_DATA`).

## Calling convention (ABI)

| Register | Use | Preserved by |
|---|---|---|
| `r0` | return value (low word for 32 bits), 1st argument word | caller |
| `r1` | high word of a 32-bit return, 2nd argument word | caller |
| `r2`, `r3` | 3rd and 4th argument words | caller |
| `r4`, `r5` | register variables | **callee** |
| `r6` = `sp` | stack pointer | callee |
| `r7` = `lr` | return address; scratch register inside a function body | caller |

- **Arguments form a sequence of words:** each argument takes the next words in order (`char`/`short`/`int`/pointer
  1 word, `long` 2 words with the low word first, a struct `size/2` words). The first 4 words go in `r0..r3`,
  the rest on the stack (at the moment of the call the 5th word is at `[sp]`, the 6th at `[sp+2]` ...). A `long`
  can be split between r3 and the stack. The **caller** removes stack arguments after the call.
- **Structs are passed by value**, copied word by word into the same sequence (so they can also end up in registers).
- **Returning a struct:** the caller allocates a result buffer and passes its address as a hidden **argument
  word 0** (`r0`); the other arguments shift by one word. The callee copies the result into the buffer and returns its address in `r0`.
- In **variadic** functions the unnamed arguments follow the same rule; `char`/`short` are promoted to
  `int`. The callee pushes r0..r3 onto the stack, so all arguments form one contiguous word sequence in
  memory and `va_list` is a plain `char *` that walks it.
- Return: 16 bits in `r0`, 32 bits in `r1:r0`, the buffer address in `r0` for a struct.

### Stack frame

Prologue: `PUSH r(n-1) … PUSH r0` (home area, if needed) · `PUSH lr` · `PUSH r4/r5` (if used) ·
`SP -= yerel_boyut` (size of the locals). The epilogue is the reverse, followed by `RET`.

```
high address
   ┌──────────────────────────────┐
   │ stack arguments (word 5…)    │  caller's area
   ├──────────────────────────────┤
   │ home area: copy of r0..r(n-1)│  here the register arguments sit next to
   │                              │  the stack arguments in memory (n ≤ 4)
   ├──────────────────────────────┤
   │ saved lr (r7)                │
   │ saved r4, r5                 │  only if there are register variables
   ├──────────────────────────────┤
   │ local variables              │  addressed with positive offsets from SP
SP → └──────────────────────────────┘
low address
```

- The home area is reserved when one of the parameters that arrive in registers was not put in a register
  variable (for example because its address is taken) or when the function is variadic; otherwise the
  parameters move straight into `r4`/`r5`.
- `lr` is normally saved, which leaves `r7` free inside the body for address calculations and far jumps.
  With optimizations on, small leaf functions that make no calls and do not touch `r7` skip
  `PUSH lr`/`POP lr` (the frame shrinks by 2 bytes).
- There is no frame pointer; locals and temporary pushes are addressed relative to SP, computed at compile time.

### Register variables

With optimizations on (the default), in each function the two most frequently used 16-bit scalar local
variables or parameters whose address is not taken and that are not `volatile` are placed in `r4` and `r5`
(uses inside loops count more). The peephole pass removes redundant jumps, `PUSH/POP` pairs, values
stored to the stack and immediately read back, and constants reloaded within the same basic block. Which
stack slot or constant each register holds is tracked across the basic block (SP adjustments included), so
a second read of the same local does not produce a new `LW`; reads of `volatile` objects are never removed.

## Linking

- Every function, global variable and string literal is a separate **piece**. The linker keeps the pieces
  reachable from `__reset` (crt0); unused functions (including library ones) do not end up in the program.
- C symbols are named `_ad` (for example `main` → `_main`), `static` ones `_ad.<dosya etiketi>` (file
  label), so two `static`s with the same name in two files do not clash.
- If the same global symbol is defined in two user files: **`'x' birden fazla tanımlı (a.c ve b.c)`**
  ('x' defined more than once). (Definitions without an initializer such as `int x;` are definitions
  too; there are no "common" symbols. Use `extern`.)
- An undefined symbol, even in unused functions: **`Tanımsız sembol: 'x' (b.c içinde kullanıldı)`**
  (undefined symbol, used in b.c).
- The library works like an archive: if the user defines the same name, the library piece is dropped (your own `putchar`, for example).
- Conditional branches reach ±256 bytes and `JAL` ±4 KB; the linker extends those that do not fit
  (`B!cc $+4 ; JAL hedef` or `LI r7, hedef ; JALR r7, r7, 0`).
- The size of `LI` follows the as16 rule; the linker's addresses are checked against as16's.

### Linkable assembly (`.s`)

`.text`, `.rodata`, `.data`, `.bss` select the section. Every label that does not start with `.` is a global
symbol and starts a new piece; labels starting with `.` and `AD = değer` constants are file-local. `CALL`
becomes an extendable call; `.org` is not allowed. Functions to be called from C are written with a `_`
prefix and follow the ABI:

```asm
        .text
_topla3:                ; int topla3(int a, int b, int c)
        ADD  r0, r0, r1
        ADD  r0, r0, r2
        RET
```

## Runtime library

| Header | Contents |
|---|---|
| `<stdio.h>` | `putchar`, `puts`, `printf`, `vprintf`, `sprintf`, `snprintf`, `vsprintf`, `vsnprintf` |
| `<stdlib.h>` | `malloc`, `calloc`, `realloc`, `free`, `abs`, `labs`, `atoi`, `atol`, `strtol`, `rand`, `srand`, `qsort`, `exit`, `abort` |
| `<string.h>` | `strlen`, `strcpy`, `strncpy`, `strcat`, `strncat`, `strcmp`, `strncmp`, `strchr`, `strrchr`, `strstr`, `memcpy`, `memmove`, `memset`, `memcmp` |
| `<ctype.h>` | `isdigit`, `isalpha`, `isalnum`, `isspace`, `isupper`, `islower`, `isxdigit`, `isprint`, `ispunct`, `toupper`, `tolower` |
| `<stdarg.h>`, `<stddef.h>`, `<stdint.h>`, `<stdbool.h>`, `<limits.h>`, `<assert.h>` | standard definitions |
| `<cpu16.h>` | `UART_DATA`, `ei`, `di`, `halt`, `irq_handler`, `swi_handler` |

- **printf:** `%d %i %u %x %X %o %c %s %p %%`, the `l` size (`%ld %lu %lx`), flags `- 0 + space #`,
  width and precision (including `*`). Output goes to the UART (0xFF00) byte by byte; UTF-8 text passes through unchanged.
- **malloc:** first-fit block list, 2-byte header, free neighbors are merged. The heap starts at the end of
  `.bss`; its limit is `__heap_end` and 256 bytes below the stack pointer.
- **Helpers (`rt.s`):** `__mul16`, `__div16`, `__udiv16`, `__mod16`, `__umod16`, `__mul32`,
  `__div32`, `__udiv32`, `__mod32`, `__umod32` (division truncates toward zero, the remainder takes the sign of the dividend),
  `__copyw`, `__copyb`, `__zerow`. CPU16 has no hardware multiply or divide; 16-bit division is a 16-step
  and 32-bit division a 32-step shift-subtract loop (with a fast 16-bit path when both high words are 0).

## BIOS target: C on the motherboard (`--hedef bios`)

The default target (`rom`) links the program to run from 0x0000 with its own vectors (it is written to the
EEPROM and replaces the BIOS). `--hedef bios` instead runs the program **on top of the BIOS**: as on the
real board and in the Web IDE, it is loaded into the monitor over the UART as Intel HEX and started with `G 4000`.

```sh
npm run cpu16 -- cc cpu16/bios/ornekler/selam.c --hedef bios --run   # on the motherboard model: BIOS + G 4000
npm run cpu16 -- cc cpu16/bios/ornekler/yilan.c --hedef bios          # yilan.hex → Web Serial / the monitor's L command
```

| | `rom` | `bios` |
|---|---|---|
| Code and constants | 0x0000–0x3FFF (ROM: EEPROM) | 0x4000–0x9FFF (RAM, windows 1–2) |
| Data, heap | 0x4000– | 0xA000– |
| Top of stack | 0xFF00 | 0xF800 (0xF800–0xFEFF holds the BIOS variables and stack) |
| crt0 | `lib/crt0.s`: vectors, SP, `.data`/`.bss`, `main`, HALT | `lib/hedef/bios/crt0.s`: saves lr and the BIOS SP, switches to its own stack, `main`, RET to the monitor |
| `putchar` / `printf` | UART data register (0xFF00) | BIOS `PUTC`: VGA screen + UART |
| `exit` | HALT | BIOS `MONITOR` |
| Interrupts | `irq_handler` (its own vectors) | the BIOS's; user hook `BIOS_SETIRQHOOK` |

The `lib/hedef/bios/*.s` files are linked like user objects; their definitions replace the library ones (crt0,
`putchar`, `exit`). `#include <bios.h>`: BIOS calls (`bios_getc`, `bios_trygetc`,
`bios_getline`, `bios_puts`, `bios_puthex4`, `bios_cls`, `bios_setcursor`, `bios_setattr`, `bios_ticks`,
`bios_setirqhook`), 16 colors and `RENK(yazı, zemin)` (foreground, background), direct screen access through
the video board's ports (`ekran_yaz(x, y, karakter, renk)`, `ekran_oku`).

- `bios_getline(tampon, en_cok)`: reads a line with echo through BIOS `GETLINE` (Backspace deletes, Enter
  finishes); including the trailing `\0`, the buffer must be at least `en_cok + 1` bytes. Returns the length read.
- `bios_setirqhook(kanca)`: installs `void kanca(int kaynak)` for the UART RX (2) and vsync (3) interrupts.
  The hook runs with interrupts disabled and must acknowledge its source (vsync: write 2 to `VSTAT`); the
  program enables the mask bit (`IRQ_MASK`, `0xFF09`) itself. Before the program ends it must clear the mask
  and call `bios_setirqhook(0)`. Example: `kesme.c`.

With the BIOS target, if stdin is a pipe or a file, `--run` sends its contents to the program over the UART
(as if typed on the keyboard); when the program returns to the monitor, the final VGA screen is printed.
`npm run cpu16 -- machine program.c` compiles and loads the same program and runs the machine in real time
with the terminal connected to the UART.

```sh
printf '2+3*4\n\n' | npm run cpu16 -- cc cpu16/bios/ornekler/hesap.c --hedef bios --run
npm run cpu16 -- machine cpu16/bios/ornekler/hesap.c        # interactive; exit: Ctrl-]
```

Examples (`cpu16/bios/ornekler/`): `yeni.c` (template), `selam.c` (printf, colors, recursion, timing),
`sayilar.c`, `uzun.c`, `kalbur.c`, `siralama.c`, `liste.c`, `hesap.c`, `sabit.c`, `ekran.c`,
`kesme.c`, `hayat.c` and **`yilan.c`**: a snake game played on the VGA screen with a PS/2 keyboard (W A S D),
the completion criterion of Phase 8. All of them are described, in a suggested order, in
[c-ornekleri.en.md](c-ornekleri.en.md). In the Web IDE you pick one under CPU16 → Motherboard + BIOS → the
example list and run it with "Compile and load to RAM"; click the screen and play with the keyboard. The tests
(`tests/cc-bios.test.ts`) load the program with the real bootloader protocol and play the game with a simple
autopilot (it eats the food, the snake grows, the score goes up; hitting a wall shows OYUN BITTI, "game over");
`tests/c-ornekleri.test.ts` compares the screen and UART output of the other examples with independently
computed results.

## Known limitations

- `float`/`double` are **not supported** (using them gives a "desteklenmiyor" (not supported) error).
- No bit fields, variable-length arrays (VLA), statement expressions `({ ... })`, K&R function definitions,
  wide string literals (`L"..."`), `_Generic` or `_Atomic`. Calling an undeclared function is an error
  (C99 rule).
- `long long` is 32 bits (same as `long`).
- Structs are aligned to at least 2 bytes and their size is rounded up to an even number (`struct { char a, b, c; }` is 4 bytes).
- `stdio.h` has no input (`getchar`, `scanf`, `gets`). On the BIOS target, keyboard / UART input is read
  through `bios.h` (`bios_getc`, `bios_trygetc`, `bios_getline`); on the ROM target `UART_DATA` can be read directly.
  The `printf` family has no `%f`, `%e` or `%n`.
- Stack overflow is not checked; deep recursion can overflow the stack into `.bss`/heap (RAM ~47 KB).
- Self-hosting is outside the scope of this phase.

## Tests

`npm test` runs the following (`cpu16/tests/cc*.test.ts`):

- **cc-ops:** every operator for int, unsigned, long and unsigned long is run on all pairs of 12 edge values
  (−32768, 32767, 0xFFFF, 0x80000000 ... ) and compared with C semantics computed in JavaScript; the same
  expressions are also tried with constant folding and with optimizations off (tens of thousands of values).
- **cc:** language features, pointer arithmetic (different element sizes), struct copy/pass/return,
  recursion depth, variadic arguments, the library, the example programs (`programs/c/`), compile errors.
- **cc-link:** preprocessor, multiple files, `static`, duplicate/undefined symbols, far branches, ROM/RAM overflow.
- **cc-bios:** the BIOS target; `selam.c` and `yilan.c` are loaded with the real bootloader protocol and run
  on the motherboard model.
- **c-ornekleri:** every C example in `cpu16/bios/ornekler/` is compiled and run on the motherboard model;
  the UART text and VRAM (characters, colors) are compared with independently computed results.

Every test program on the ROM target runs on the ROM-guarded bus and is checked to never write below 0x4000.
