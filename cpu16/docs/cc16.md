# cc16 — CPU16 için C Derleyicisi (Faz 8)

cc16, CPU16 için TypeScript ile yazılmış bir C derleyicisidir. Dosya sistemine dokunmadığı için aynı kod
hem Node komut satırında hem tarayıcıda çalışır. Çıktısı as16 ile derlenen tek bir assembly metnidir;
bu sayede derlenen her program, elle yazılmış programlarla aynı emülatörde, mikrokod modelinde ve
gerçek kartta çalışır.

```
kaynak.c ─► önişlemci ─► ayrıştırıcı (tipli AST + sabit katlama) ─► kod üreteci ─► nesne (parçalar)
                                                                                      │
crt0.s, rt.s, libc16.c (kütüphane) ─────────────────────────────────────► bağlayıcı ◄─┘
                                                                              │
                                                       as16 metni ─► as16 ─► 64 KB imaj (ROM 0x0000–0x3FFF)
```

| Dosya | Görev |
|---|---|
| `cc/lexer.ts` | sözcük çözümleyici (pp-token'lar, string/karakter kaçışları, UTF-8) |
| `cc/preprocess.ts` | `#include`, `#define`, `#if` ailesi, `#` / `##`, `__VA_ARGS__` |
| `cc/parser.ts` | C ayrıştırıcı, tip denetimi, örtük dönüşümler, sabit katlama, başlatıcılar |
| `cc/codegen.ts` | kod üretimi, register değişkenleri, gözetleme deliği iyileştirmeleri |
| `cc/object.ts` | nesne biçimi ("parça" listesi), `.s` dosyalarını nesneye çevirme |
| `cc/linker.ts` | sembol çözümleme, ölü kod atma, ROM/RAM yerleşimi, dallanma uzatma |
| `cc/index.ts` | genel API: `compile`, `buildProgram` |
| `cc/run.ts` | emülatörde çalıştırma, ROM'a yazmayı yakalayan veriyolu |
| `cc/node.ts` / `cc/lib-vite.ts` | kütüphaneyi diskten (Node) / pakete gömülü (Vite, tarayıcı) yükleme |
| `lib/` | `crt0.s`, `rt.s` (yardımcılar), `libc16.c`, `include/*.h` |
| `tools/cc.ts` | `cc` komut satırı |

## Kullanım

```sh
npm run cpu16 -- cc cpu16/programs/c/hello.c --run          # derle ve emülatörde çalıştır
npm run cpu16 -- cc program.c                               # program.hex (Intel HEX, EEPROM için)
npm run cpu16 -- cc program.c -o program.bin                # ham ikili (0x0000'dan)
npm run cpu16 -- cc program.c -o program.s                  # bağlanmış as16 metni
npm run cpu16 -- cc cpu16/programs/c/multi/main.c cpu16/programs/c/multi/util.c --run
npm run cpu16 -- cc a.c b.c rutin.s -I include -D DEBUG=1 --map --run
```

| Seçenek | Anlam |
|---|---|
| `-o dosya` | çıktı: `.hex` (varsayılan), `.bin` ya da `.s` |
| `--run` | emülatörde çalıştır; UART çıktısı (0xFF00) konsola yazılır, sonunda çıkış kodu |
| `--max N` | en fazla N komut (varsayılan 50 milyon) |
| `-I dizin` | `#include "..."` için ek arama dizini |
| `-D AD[=değer]` | makro tanımla |
| `-O0` | register değişkenleri ve gözetleme deliği iyileştirmelerini kapat |
| `--nostdlib` | crt0 ve kütüphaneyi bağlama (`__reset`'i program tanımlar) |
| `--map` | parçaların adres/boyut tablosu |

Girdi dosyaları `.c` ya da `.s` (bağlanabilir assembly, aşağıya bakın) olabilir.

### API (tarayıcı ve Node)

```ts
import { buildProgram, compile, formatErrors } from "./cpu16/cc/index.ts";
import { LIB } from "./cpu16/cc/lib-vite.ts";   // Node'da: import { loadLib } from "./cpu16/cc/node.ts"
import { runProgram } from "./cpu16/cc/run.ts";

const files = { "/proje/main.c": "...", "/proje/util.h": "..." };       // bellek içi dosya sistemi
const b = buildProgram(files, ["/proje/main.c"], { lib: LIB, defines: { N: "10" } });
if (b.errors.length) console.log(formatErrors(b.errors));            // [{ file, line, col, message }]
else console.log(runProgram(b.image).output);                         // b.ranges, b.symbols, b.map, b.asm

const c = compile(files, ["/proje/main.c"], { lib: LIB });            // { asm, errors }: yalnızca as16 metni
```

Seçenekler: `lib`, `nostdlib`, `defines`, `includeDirs`, `readFile` (haritada olmayan dosyalar için geri
çağrı), `optimize` (varsayılan `true`), `layout` (ROM/RAM sınırları). Kütüphanenin derlenmiş hali aynı
`lib` nesnesi için önbelleğe alınır.

## Desteklenen C

C99'un büyük kısmı (Faz 8 kapsamı, aşama 1–4):

- **Tipler:** `char` (8 bit, **işaretsiz**), `signed/unsigned char`, `short` ve `int` (16 bit), `long` ve
  `long long` (32 bit), `_Bool`/`bool`, `enum` (int), işaretçiler (16 bit), diziler (çok boyutlu dahil),
  `struct`, `union` (anonim üyeler, esnek dizi üyesi), fonksiyon işaretçileri, `typedef`, `const`, `volatile`.
- **Deyimler:** `if/else`, `while`, `do/while`, `for` (bildirimli başlangıç dahil), `break`, `continue`,
  `return`, `switch/case/default` (sıkışık durumlar atlama tablosu), `goto` ve etiketler, bloklar.
- **İfadeler:** bütün tamsayı operatörleri (`* / %` ve değişken kaydırmalar yazılım yardımcılarıyla),
  işaretli/işaretsiz karşılaştırmalar, `&& || !` (kısa devre), `?:`, virgül, bileşik atamalar, `++/--`,
  `sizeof`, dönüşümler (cast), işaretçi aritmetiği ve farkı, struct ataması / değerle geçirme / döndürme,
  bileşik sabitler `(struct P){1, 2}`, `__func__`.
- **Başlatıcılar:** global ve yerel diziler, struct'lar, string'ler, iç içe ve gösterge (designator)
  kullanan başlatıcılar (`.a.b = 1`, `[3].x = 2`), boyutu başlatıcıdan çıkan diziler, adres sabitleri
  (`int *p = &dizi[2];`, fonksiyon işaretçisi tabloları).
- **Değişken argümanlı fonksiyonlar:** `<stdarg.h>` (`va_list`, `va_start`, `va_arg`, `va_end`, `va_copy`).
- **Önişlemci:** `#include "..."` (önce dosyanın dizini, sonra `-I` dizinleri) ve `<...>` (kütüphane
  başlıkları), nesne/fonksiyon benzeri `#define`, `#`, `##`, `__VA_ARGS__`, `, ## __VA_ARGS__`, `#undef`,
  `#if/#ifdef/#ifndef/#elif/#else/#endif`, `defined`, `#error`, `#warning`, `#pragma once`, `#line`,
  `__FILE__`, `__LINE__`; önceden tanımlı `__CPU16__`, `__CC16__`, `__CHAR_UNSIGNED__`, `__SIZEOF_INT__` ...
- **Birden çok çeviri birimi:** `extern`, `static` (dosyaya özel fonksiyon ve değişkenler), assembly
  dosyalarıyla karışık bağlama.

Sabit ifadeler (dizi boyutları, `case` değerleri, global başlatıcılar, `#if`) derleme zamanında,
hedefin 16/32 bit kurallarıyla hesaplanır; aynı katlama fonksiyon gövdelerindeki sabit alt ifadelere de uygulanır.

### Tip boyutları ve hizalama

| Tip | Boyut | Hizalama |
|---|---|---|
| `char`, `_Bool` | 1 | 1 |
| `short`, `int`, işaretçi, `enum` | 2 | 2 |
| `long`, `long long` | 4 (düşük kelime önce) | 2 |
| `struct` / `union` | üyelere göre, **çift sayıya yuvarlanır** | 2 |

Ondalık sabitler `int`'e sığmazsa `long` olur (`32768` → `long`, bu yüzden `-32768` de `long`'dur;
`INT_MIN` `(-32767 - 1)` olarak tanımlıdır). Onaltılık/sekizlik sabitler `int`'e sığmazsa `unsigned int` olur (`0xFFFF` → `unsigned`).
Yerel değişkenlerin hepsi çift adreste ve çift boyutlu yuvadadır; struct kopyalama kelime kelime yapılır.

## Bellek yerleşimi

```
0x0000 ┌──────────────────────────┐  ROM (yazmalar yok sayılır)
       │ vektörler: 0x0000 reset  │  her biri tek komut (B .start / B .irq / B .swi)
       │            0x0002 IRQ    │
       │            0x0004 SWI    │
       │ crt0, .text (kod)        │  kullanıcı kodu, sonra kütüphane
       │ .rodata (const, string)  │
       │ .data ilk değer imajı    │  __data_load
0x3FFF └──────────────────────────┘
0x4000 ┌──────────────────────────┐  RAM
       │ .data (ilk değerli)      │  __data_start … __data_end   (crt0 imajı buraya kopyalar)
       │ .bss  (sıfır)            │  __bss_start … __bss_end     (crt0 sıfırlar)
       │ yığın (heap) ↑ malloc    │  __heap_start … __heap_end (= 0xFF00 − 0x400)
       │          ...             │
       │ yığın (stack) ↓          │  SP başlangıcı __stack_top = 0xFF00
0xFEFF └──────────────────────────┘
0xFF00   G/Ç: UART veri register'ı (putchar buraya yazar)
```

- Kod ve sabitler (`const` globaller, string sabitleri) ROM'dadır. Program ROM'a hiç yazmaz; testlerde
  0x4000 altına yapılan her yazma sayılır ve sıfır olduğu doğrulanır (`cc/run.ts: RomGuardBus`).
- İlk değerli değiştirilebilir globaller (`.data`) RAM'de yaşar; ilk değerleri ROM'da `__data_load`'daki
  imajdadır. **crt0 açılışta bu imajı RAM'e kopyalar** ve `.bss`'i sıfırlar, sonra `main(0, 0)`'ı çağırır.
- `main` dönünce dönüş değeri `r0`'da kalarak `HALT` çalışır (`exit(n)` de aynısını yapar).
- Bağlayıcı; ROM 16 KB'yi, RAM `.data + .bss + 1 KB yığın`'ı aşarsa "ROM taştı" / "RAM taştı" hatası verir.

### crt0 sırası

1. `0x0000: B .start`, `0x0002: B .irq`, `0x0004: B .swi`
2. `SP = 0xFF00`
3. `__data_load → __data_start..__data_end` kelime kelime kopya
4. `__bss_start..__bss_end` sıfırlanır
5. `r0 = r1 = 0`, `CALL _main`, `HALT` (çıkış kodu `r0`)

IRQ/SWI girişi r0–r3 ve r7'yi saklayıp C'deki `irq_handler()` / `swi_handler()`'ı çağırır, sonra `RETI`.
Kütüphanede boş varsayılanları vardır; programda tanımlanan aynı adlı fonksiyon onların yerine geçer
(`<cpu16.h>`: `ei()`, `di()`, `halt()`, `UART_DATA`).

## Çağrı kuralı (ABI)

| Register | Kullanım | Kim korur |
|---|---|---|
| `r0` | dönüş değeri (32 bitte düşük kelime), 1. argüman kelimesi | çağıran |
| `r1` | 32 bit dönüşte yüksek kelime, 2. argüman kelimesi | çağıran |
| `r2`, `r3` | 3. ve 4. argüman kelimesi | çağıran |
| `r4`, `r5` | register değişkenleri | **çağrılan** |
| `r6` = `sp` | yığın işaretçisi | çağrılan |
| `r7` = `lr` | dönüş adresi; fonksiyon gövdesinde geçici register | çağıran |

- **Argümanlar bir kelime dizisidir:** her argüman sırayla kelimelere yerleşir (`char`/`short`/`int`/işaretçi
  1 kelime, `long` 2 kelime — önce düşük kelime, struct `boyut/2` kelime). İlk 4 kelime `r0..r3`'te,
  kalanlar yığındadır (5. kelime çağrı anında `[sp]`'de, 6. `[sp+2]`'de ...). Bir `long` r3 ile yığın
  arasında bölünebilir. Yığındaki argümanları çağrıdan sonra **çağıran** temizler.
- **Struct'lar değerle** kelime kelime aynı diziye kopyalanır (yani register'larda da olabilir).
- **Struct döndürme:** çağıran bir sonuç tamponu ayırır ve adresini gizli **0. argüman kelimesi** (`r0`)
  olarak geçirir; diğer argümanlar bir kelime kayar. Çağrılan sonucu tampona kopyalar ve adresini `r0`'da döndürür.
- **Değişken argümanlı** fonksiyonlarda adlandırılmamış argümanlar da aynı kurala uyar; `char`/`short`
  `int`'e terfi eder. Çağrılan r0..r3'ü yığına attığı için bütün argümanlar bellekte bitişik bir kelime
  dizisi olur ve `va_list` basit bir `char *` olarak bu diziyi gezer.
- Dönüş: 16 bit `r0`, 32 bit `r1:r0`, struct için tampon adresi `r0`.

### Yığın çerçevesi

Prolog: `PUSH r(n-1) … PUSH r0` (ev alanı, gerekirse) · `PUSH lr` · `PUSH r4/r5` (kullanılıyorsa) ·
`SP -= yerel_boyut`. Epilog bunun tersidir; sonra `RET`.

```
yüksek adres
   ┌──────────────────────────────┐
   │ yığındaki argümanlar (5. kelime…) │  çağıranın alanı
   ├──────────────────────────────┤
   │ ev alanı: r0..r(n-1) kopyası  │  register argümanları burada bellekteki
   │                              │  yığın argümanlarıyla bitişik olur (n ≤ 4)
   ├──────────────────────────────┤
   │ kaydedilen lr (r7)           │
   │ kaydedilen r4, r5            │  yalnızca register değişkeni varsa
   ├──────────────────────────────┤
   │ yerel değişkenler            │  SP'ye göre pozitif ofsetlerle adreslenir
SP → └──────────────────────────────┘
düşük adres
```

- Ev alanı, register'la gelen parametrelerden biri register değişkenine konmadıysa (ör. adresi alındıysa)
  ya da fonksiyon değişken argümanlıysa ayrılır; aksi halde parametreler doğrudan `r4`/`r5`'e taşınır.
- `lr` normalde kaydedilir; bu sayede `r7` gövdede adres hesabı ve uzak atlamalar için serbesttir.
  İyileştirmeler açıkken, hiç çağrı yapmayan ve `r7`'ye dokunmayan küçük yaprak fonksiyonlarda
  `PUSH lr`/`POP lr` atlanır (çerçeve 2 bayt küçülür).
- Çerçeve işaretçisi yoktur; yerel değişkenler ve geçici itmeler SP'ye göre derleme zamanında hesaplanır.

### Register değişkenleri

İyileştirmeler açıkken (varsayılan) her fonksiyonda adresi alınmayan, `volatile` olmayan 16 bitlik en sık
kullanılan iki skaler yerel değişken/parametre `r4` ve `r5`'e konur (döngü içindeki kullanımlar ağırlıklı
sayılır). Gözetleme deliği aşaması gereksiz atlamaları, `PUSH/POP` çiftlerini, yığına yazılıp hemen geri
okunan değerleri ve aynı temel blokta tekrar yüklenen sabitleri siler. Register'larda hangi yığın
yuvasının/sabitin tutulduğu temel blok boyunca izlenir (SP kaymaları hesaba katılır), böylece aynı
yerel değişkenin ikinci okuması yeni bir `LW` üretmez; `volatile` nesnelerin okumaları hiçbir zaman silinmez.

## Bağlama

- Her fonksiyon, global değişken ve string sabiti ayrı bir **parça**dır. Bağlayıcı `__reset`'ten
  (crt0) erişilebilen parçaları tutar; kullanılmayan fonksiyonlar (kütüphanedekiler dahil) programa girmez.
- C sembolleri `_ad` olarak (ör. `main` → `_main`), `static` olanlar `_ad.<dosya etiketi>` olarak
  adlandırılır; böylece iki dosyadaki aynı adlı `static`'ler çakışmaz.
- Aynı global sembol iki kullanıcı dosyasında tanımlıysa: **`'x' birden fazla tanımlı (a.c ve b.c)`**.
  (`int x;` gibi ilk değersiz tanımlar da tanımdır, "common" sembol yoktur — `extern` kullanın.)
- Tanımsız sembol, kullanılmayan fonksiyonlarda bile: **`Tanımsız sembol: 'x' (b.c içinde kullanıldı)`**.
- Kütüphane bir arşiv gibidir: kullanıcı aynı adı tanımlarsa kütüphanedeki parça atılır (ör. kendi `putchar`'ınız).
- Koşullu dallanmalar ±256 bayta, `JAL` ±4 KB'ye ulaşır; bağlayıcı sığmayanları uzatır
  (`B!cc $+4 ; JAL hedef` ya da `LI r7, hedef ; JALR r7, r7, 0`).
- `LI`'nin boyutu as16 kuralıyla hesaplanır; bağlayıcının adresleri as16'nınkilerle karşılaştırılır.

### Bağlanabilir assembly (`.s`)

`.text`, `.rodata`, `.data`, `.bss` bölüm seçer; `.` ile başlamayan her etiket global bir semboldür ve
yeni bir parça başlatır, `.` ile başlayanlar ve `AD = değer` sabitleri dosyaya özeldir. `CALL` uzatılabilir
çağrıya dönüşür; `.org` kullanılamaz. C'den çağrılacak fonksiyonlar `_` önekiyle yazılır ve ABI'ye uyar:

```asm
        .text
_topla3:                ; int topla3(int a, int b, int c)
        ADD  r0, r0, r1
        ADD  r0, r0, r2
        RET
```

  `__copyw`, `__copyb`, `__zerow`. CPU16'da donanım çarpma/bölme yoktur; 16 bitlik bölme 16, 32 bitlik
  bölme 32 adımlı kaydır-çıkar döngüsüdür (iki üst kelime de 0 ise 16 bitlik hızlı yol).

## BIOS hedefi: anakartta C (`--hedef bios`)

Varsayılan hedef (`rom`) programı 0x0000'dan, kendi vektörleriyle çalışacak şekilde bağlar (Flash'a
yazılır, BIOS'un yerine geçer). `--hedef bios` ise programı **BIOS'un üzerinde** çalıştırır: gerçek
kartta ve Web IDE'de olduğu gibi monitöre UART'tan Intel HEX olarak yüklenir ve `G 4000` ile başlar.

```sh
npm run cpu16 -- cc cpu16/bios/ornekler/selam.c --hedef bios --run   # anakart modelinde: BIOS + G 4000
npm run cpu16 -- cc cpu16/bios/ornekler/yilan.c --hedef bios          # yilan.hex → Web Serial / monitörün L komutu
```

| | `rom` | `bios` |
|---|---|---|
| Kod ve sabitler | 0x0000–0x3FFF (Flash) | 0x4000–0x9FFF (RAM, pencere 1–2) |
| Veri, yığın (heap) | 0x4000– | 0xA000– |
| Yığın tepesi | 0xFF00 | 0xF800 (0xF800–0xFEFF BIOS'un değişkenleri ve yığını) |
| crt0 | `lib/crt0.s`: vektörler, SP, `.data`/`.bss`, `main`, HALT | `lib/hedef/bios/crt0.s`: lr ve BIOS'un SP'sini saklar, kendi yığınına geçer, `main`, monitöre RET |
| `putchar` / `printf` | UART veri register'ı (0xFF00) | BIOS `PUTC`: VGA ekran + UART |
| `exit` | HALT | BIOS `MONITOR` |
| Kesmeler | `irq_handler` (kendi vektörleri) | BIOS'un; kullanıcı kancası `BIOS_SETIRQHOOK` |

`lib/hedef/bios/*.s` dosyaları kullanıcı nesnesi gibi bağlanır; tanımları kütüphanedekilerin (crt0,
`putchar`, `exit`) yerine geçer. `#include <bios.h>`: BIOS çağrıları (`bios_getc`, `bios_trygetc`,
`bios_puts`, `bios_cls`, `bios_setcursor`, `bios_setattr`, `bios_ticks`), 16 renk ve `RENK(yazı, zemin)`,
video kartının portlarıyla doğrudan ekran erişimi (`ekran_yaz(x, y, karakter, renk)`, `ekran_oku`).

Örnekler (`cpu16/bios/ornekler/`): `selam.c` (printf, renkler, özyineleme, süre ölçümü) ve **`yilan.c`**:
VGA ekranda, PS/2 klavyeyle (W A S D) oynanan yılan oyunu, Faz 8'in bitiş ölçütü. Web IDE'de
CPU16 → Anakart + BIOS → örnek listesinden seçilip "Derle ve RAM'e yükle" ile çalışır; ekrana tıklayıp
klavyeyle oynanır. Testler (`tests/cc-bios.test.ts`) programı gerçek önyükleyici protokolüyle yükler ve
oyunu basit bir otomatik pilotla oynatır (yem yenir, yılan uzar, skor artar; duvara çarpınca OYUN BITTI).

## Bilinen sınırlamalar

- `float`/`double` **desteklenmiyor** (kullanımı "desteklenmiyor" hatası verir).
- Bit alanları, değişken uzunluklu diziler (VLA), deyim ifadeleri `({ ... })`, K&R fonksiyon tanımları,
  geniş karakterli string'ler (`L"..."`), `_Generic`, `_Atomic` yok. Bildirimsiz fonksiyon çağrısı hatadır
  (C99 kuralı).
- `long long` 32 bittir (`long` ile aynı).
- Struct'lar en az 2 bayt hizalıdır ve boyutları çift sayıya yuvarlanır (`struct { char a, b, c; }` 4 bayt).
- Girdi (stdin) yok; `printf` ailesinde `%f`, `%e`, `%n` yok.
- Yığın taşması denetlenmez; derin özyinelemede yığın `.bss`/heap'e taşabilir (RAM ~47 KB).
- Kendi kendini derleme (self-hosting) bu fazın kapsamında değil.

## Testler

`npm test` şunları çalıştırır (`cpu16/tests/cc*.test.ts`):

- **cc-ops:** int, unsigned, long, unsigned long için bütün operatörler 12 uç değerin bütün çiftleriyle
  (−32768, 32767, 0xFFFF, 0x80000000 ... ) çalıştırılıp JavaScript'te hesaplanan C semantiğiyle
  karşılaştırılır; aynı ifadeler sabit katlamayla ve iyileştirmeler kapalıyken de denenir (on binlerce değer).
- **cc:** dil özellikleri, işaretçi aritmetiği (farklı eleman boyutları), struct kopyalama/geçirme/döndürme,
  özyineleme derinliği, değişken argümanlar, kütüphane, örnek programlar (`programs/c/`), derleme hataları.
- **cc-link:** önişlemci, çoklu dosya, `static`, çift/tanımsız sembol, uzak dallanmalar, ROM/RAM taşması.

Her test programı ROM korumalı veriyolunda çalışır ve 0x4000 altına hiç yazmadığı doğrulanır.
